# Rationalizations and red flags

The excuses a model reaches for when a writing task gets hard, each with the rebuttal that
applies. Every writer skill and the validator read this file. A skill adds only the rows that are
specific to its genre, in its own `## Red flags` section.

## Rationalizations

| When you think | Do this instead |
|---|---|
| "The evidence is thin, I will infer the status from context." | Write the status the evidence supports and put the inference under Known Gaps marked (unverified). An inferred GREEN is the single most expensive error this document can carry. |
| "The source was unavailable, I will use what I remember from last time." | Say so in the Sources header (`unavailable: <role>`) and in Known Gaps. A reader who knows a source was down trusts the rest. |
| "This number is close enough." | A number is quoted exactly or not at all. Round only when the evidence rounds, and say which. |
| "The reader knows what I mean." | The reader spends thirty seconds and has none of your context. Name the thing, the number and the source. |
| "I already ran the gate once, a second pass will find nothing." | The minimum is two passes because the first fix introduces the second defect. Run it. |
| "The gate found no blockers, so the draft is verified." | A passed rule names what it checked. A report that says `verified` with nothing quoted has checked nothing. |
| "The deadline passed, so the item must be done." | A passed date is evidence of a passed date. Status comes from a status field, a message, or a ticket state, never from the calendar. |
| "I will add a sentence explaining how carefully I checked this." | Process sentences are deleted at the gate. The evidence of care is the citation beside the claim. |
| "Two sources disagree, I will pick the more recent one." | Record both with their sources and dates and flag the conflict. Choosing silently hides the fact a leader most needs. |
| "This superlative is justified here." | It is never justified in this register. Replace it with the fact that would have justified it. |
| "I will mention the person's rating to make the argument clearer." | Rating placement is a mechanical rule per document type. Outside its table it is a blocker, and in a work summary or promo document it never appears. |
| "The template section does not apply, I will skip it." | Every section is rendered. An empty one says why (`none this period`, `not supplied`), so the reader knows it was considered. |

## Red flags

Stop and re-read the rule when you see yourself doing any of these:

- a status word (GREEN, on track, done, de-risked) with no artifact in the same sentence
- a date in the future written in the past tense
- the words `should`, `likely`, `probably`, `roughly`, `several` in a claim
- a link whose text is not the artifact's own name
- a paragraph that could be pasted into any other program's update unchanged
- a Known Gaps section that is empty when a source was unavailable
- a reply that describes the writing instead of being the document
